## 10. What this run did NOT verify

  * The Kubernetes restart action itself. The manifests validate against a
    real 1.36 API server (section 9), and the probe that triggers a restart
    is shown failing on a wedged node (section 7), but the local cluster is
    kind-based with its own image store and the connection here was too
    slow to populate it, so no pod was run from these images.
  * The nginx-prometheus-exporter target (section 8, 'down'): its image was
    not pulled for the same reason. Nginx's stub_status endpoint itself is
    served and reachable.
  * The HorizontalPodAutoscalers. The scraper's external-metric trigger
    needs prometheus-adapter installed in the cluster.

## 11. Bugs this run found, which no test had caught

  1. Kafka's EXTERNAL listener was never published, so no client outside
     the compose network could reach the broker.
  2. A commit rejected after a rebalance (ILLEGAL_GENERATION) escaped and
     killed a crawler node; it is a routine protocol event.
  3. depth() joined the consumer group to read offsets, rebalancing the
     live fleet on every call; it now uses the admin API.
  4. Nodes exited after ~6s of an empty frontier, and 'restart: always'
     turned that into a restart loop that rejoined the consumer group
     every few seconds, so the group never stabilised and no work was
     picked up (13-14 restarts per node). Nodes now wait indefinitely and
     write a heartbeat while idle, so 'idle' is distinguishable from
     'wedged'.
  5. The compose tmpfs for the heartbeat was root-owned, so the non-root
     user could not write it and the node was reported unhealthy forever.
  6. Nginx listened on IPv4 only while its health check resolved localhost
     to ::1, marking a perfectly healthy balancer unhealthy.
  7. nginx-exporter depended on a service in a different compose profile,
     which made 'docker compose --profile monitoring up' an invalid project.
  8. Redis published on 6379 clashed with another project on this machine.
  9. 'return' in the nginx config was split over several quoted strings,
     which nginx does not concatenate - the container would not start.
